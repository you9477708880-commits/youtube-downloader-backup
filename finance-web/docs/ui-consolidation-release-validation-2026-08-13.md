# 介面整併與發布驗證（2026-08-13）

## 目標

在不新增資料欄位、不改帳務公式與同步語意的前提下，降低「目標中心 A」與「搜尋紀錄 A」同時出現後的首屏資訊量與日期概念混淆。

## 介面整併

### 目標中心

- 首屏保留目標摘要與期限不足提醒。
- 完整的「準備中／考慮中」清單改為按需展開，避免與頁面下方原有大額準備、待購清單管理區同時大量重複顯示。
- 展開後仍保留全部／準備中／考慮中篩選，以及查看、調整與建立準備等既有操作。
- 篩選造成重新 render 時保留展開狀態；重新載入頁面後回到簡潔的收合狀態。
- 手機版三個摘要採緊湊的標籤／金額列，完整清單維持單欄。

### 搜尋紀錄

- 未搜尋時明確顯示「搜尋期間獨立，不影響月度報表」。
- 搜尋中仍在日期摘要前重複標示此邊界，避免把搜尋半年誤認為全站報表也切換半年。
- 自訂日期仍只在選擇自訂區間後出現，清除後回到近 6 個月並收起日期欄位。

## 保持不變

- `txs`、`sinkingFunds.events` 與既有預算公式。
- state schema、migration、normalize、JSON／AndroMoney 匯入匯出。
- localStorage／UID scope、Firestore record codec、Rules、Functions。
- 搜尋條件與目標篩選仍是暫時 UI 狀態，不保存也不上雲。

## 自動與操作驗證

- 目標中心 view tests：預設收合、展開狀態保留、篩選、escape 與空資料。
- 搜尋 controller tests：未搜尋與搜尋中都標示日期邊界。
- browser smoke：完整 13 個情境，包含待購預填、搜尋與目標中心隔離。
- 本機預覽桌機：目標中心摘要、收合入口及原有管理區正常。
- 本機預覽 390 × 844：無水平溢出；摘要、展開、搜尋、自訂期間與清除皆可操作。

## 發布邊界

本批只建立本機提交。等待人工驗收後，再決定是否推送本批介面整併與部署 Firebase Hosting；不部署 Firestore Rules 或 Firebase Functions。
