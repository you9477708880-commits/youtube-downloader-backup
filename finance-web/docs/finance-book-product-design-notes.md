# 理財書籍產品設計筆記

來源：`刷新你的金錢腦【財富自由5階梯實戰祕笈】...epub`

用途：這份筆記只作為產品設計參考，不作為書籍摘要、投資建議或網站文案來源。若未來要把概念放進網站，應用我們自己的文字重新設計。

## 1. 書中對產品有用的核心框架

這本書的主軸不是單純「省錢」，而是把財務獨立拆成一段可持續的旅程。對我們的網站有用的地方在於，它把理財分成幾個可以產品化的層次：

- 財務旅程是分階段的，不是只有「自由 / 不自由」二分法。
- 財務狀態可以用六個要素理解：收入、支出、負債、資產、心態、習慣。
- 收入和支出是槓桿，會創造出理財餘裕。
- 理財餘裕再分配到償債、儲蓄、投資、生活品質與人生目標。
- 支出不只要壓低，而是要區分必要、非必要、值得保留的生活品質。
- 退休或財務獨立估算應該支援情境試算，因為人生會改變。

這些概念和目前網站方向一致：記帳不是終點，重點是讓使用者理解自己現在的位置、下一步該調整什麼。

## 2. 對現有功能的映射

### 記帳

目前交易紀錄已能記收入、支出、轉帳、代墊與還款。書中的觀點提醒我們，未來交易分類不應只停在「餐飲 / 交通」這類消費分類，還可以增加一層用途判斷：

- 必要支出
- 彈性支出
- 生活品質支出
- 目標型支出

這不一定要立刻進資料模型，但在未來分類模型升級時可以保留擴充空間。

### 預算與可自由運用

網站目前的「可自由運用」很接近書中提到的理財餘裕概念。它不只是收入減支出，而是扣掉生活支出、大額準備、手動補入後，真正還能被分配的空間。

產品上可以把它定位得更清楚：

- 這是使用者每月可以重新分配的行動空間。
- 它可以用來加速大額準備、償債、投資或保留生活品質。
- 它不應被設計成單純「剩多少錢」。

### 大額支出準備

書中強調人生目標與財務目標的關係。這支持我們目前把大額準備放在核心位置，而不是把大額支出事後平均攤回。

大額準備可以被視為：

- 把人生目標轉成每月行動。
- 把未來支出提前納入當月預算。
- 減少臨時大額支出對財務狀態的衝擊。

這和目前 `sinkingFunds.events` 的事件制方向相容。

### 資產負債

書中把淨資產視為理解財務階段的重要指標。網站目前已有資產負債頁，後續可以考慮讓它更接近「階段判斷」而不只是列表：

- 淨值是否為正。
- 負債是否吃掉太多收入。
- 緊急備用金是否足夠。
- 可投資資產是否正在增加。

### 退休估算

書中支持「個人估算器」定位，而不是一開始就做複雜投資模擬。更有價值的是情境理解：

- 如果短期少投資幾年，退休目標會延後多少。
- 如果生活支出提高，目標資產會變多少。
- 如果收入增加，目標達成時間能縮短多少。

這些是情境試算，不一定要變成複雜金融模型。

## 3. 值得加入的產品概念

### A. 財務階段視圖

可以設計一個簡單的「目前財務階段」區塊，但不要硬套書中的名稱。網站可以用自己的階段，例如：

- 整理資料中
- 建立緊急備用金
- 降低高壓負債
- 穩定累積資產
- 財務彈性提升中
- 接近退休 / 財務獨立

第一版不要自動給結論，可以先用使用者自選或半自動提示。

### B. 六要素總覽

總覽頁未來可以把指標分成六組：

- 收入：本月收入、收入來源數、收入穩定性。
- 支出：生活支出、可自由運用、分類預算。
- 負債：負債總額、每月還款壓力。
- 資產：淨值、緊急備用金、可投資資產。
- 心態：使用者自評，不用硬量化。
- 習慣：記帳連續性、預算回顧頻率。

心態與習慣不應強行做成評分，否則會有說教感。比較適合做成月度回顧問題。

### C. 生活品質等級

書中「生活品質等級」的概念很適合轉成產品設定：

- 基本生活版
- 穩定舒適版
- 重視體驗版
- 加速財務自由版

這可以影響退休估算、預算建議與目標設定。不過第一版應該只當情境標籤，不要自動改使用者預算。

### D. 目標時間框架

待購清單與大額準備未來可以統一成目標系統：

- 短期：1 年內
- 中期：1 到 5 年
- 長期：5 年以上

每個目標應該可以看到：

- 目標金額
- 目標月份
- 每月需要準備多少
- 目前是否可達成
- 若不可達成，差多少

目前大額準備已經有一部分能力，後續可以和待購清單整合。

### E. 支出最佳化，而不是支出羞辱

書中的觀點不是極端節省，而是把錢用在真正有價值的地方。這點很重要。

網站未來如果做支出分析，不應該只顯示「你花太多」，而是：

- 哪些支出是固定必要。
- 哪些支出可調整。
- 哪些支出雖然非必要，但使用者願意保留。
- 哪些支出和長期目標衝突。

這會讓網站更像理財作業系統，而不是單純記帳檢討工具。

## 4. 不建議現在做的方向

- 不要把書中財務自由階段完整搬進網站。
- 不要直接複製書中文案。
- 不要把退休頁擴張成複雜投資模擬器。
- 不要用 AI 或公式替使用者判斷人生選擇。
- 不要把心態與習慣做成過度量化的分數。
- 不要做會讓使用者有羞辱感的消費評語。

## 5. 對 roadmap 的可能影響

這本書支持我們目前的優先順序：

1. 先穩定記帳、預算、大額準備、資產負債與退休估算。
2. 再做分類模型升級，因為未來不只需要主分類 / 子分類，也可能需要必要性、生活品質、目標關聯等維度。
3. 桌機版可以之後再做，但總覽頁未來應更像一個「財務狀態儀表板」。
4. 退休頁應維持個人估算器定位，加入情境比較即可，不必做成投資平台。
5. 大額準備和待購清單未來可以往「目標系統」整合。

## 6. 建議的實作順序

### 近期

- 保持目前 roadmap：先做交易分類模型升級與 AndroMoney 前置條件。
- 在分類模型設計時預留 `subcategory` 以外的未來擴充欄位。
- 不要急著加入心態、習慣、生活品質等級。

### 中期

- 改善總覽頁，讓收入、支出、負債、資產四個量化要素更容易掃描。
- 將待購清單與大額準備的關係整理成目標系統。
- 讓退休頁支援簡單情境比較。

### 長期

- 加入月度回顧：本月理財餘裕、支出調整、目標進度、下月行動。
- 加入使用者自選的生活品質情境。
- 加入財務階段視圖，但以提示和自評為主，不做武斷判斷。

## 7. 結論

這本書對網站最有價值的啟發是：理財工具不應只記錄過去花了什麼，而應該幫使用者理解「我現在在哪裡、我想去哪裡、這個月的錢要如何分配」。

因此，網站後續可以朝「個人財務導航系統」前進，但仍要保持目前的保守工程原則：帳務事實、預算規劃、準備金事件與退休推估必須分清楚。
