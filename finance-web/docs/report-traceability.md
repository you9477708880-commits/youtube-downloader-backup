# 報表追溯設計

這份文件定義「報表數字要能追到來源明細」的維護標準。目標是讓使用者看到總數時，可以理解這個數字從哪些交易來，而不是只能相信黑盒結果。

## 核心原則

- 總數應該可以追溯到交易明細或明確標示為手動項目。
- 不同報表可以用不同視角解讀同一筆交易，但不應複製交易資料。
- 明細展開 UI 應盡量共用同一個 renderer，避免每個報表各寫一套。
- 若某個項目不是由交易推導，應標示為手動資產或手動負債。

## 目前追溯狀態

| 報表 | 數字 | 追溯來源 | 狀態 |
| --- | --- | --- | --- |
| 資產負債表 | 帳戶餘額 | `accounts.initialBalance` + `txs` | 已支援展開帳戶明細 |
| 資產負債表 | 代墊應收款 | `advance` - `advance_repayment` | 可由代墊資料推導 |
| 資產負債表 | 手動資產 | `bsI` | 手動項目，非交易明細 |
| 資產負債表 | 手動負債 | `bsI` | 手動項目，非交易明細 |
| 現金流 | 營運收入 | 指定收入分類 | 已支援展開明細 |
| 現金流 | 生活與日常支出 | `expense.amount` + `advance.ownAmount` | 已支援展開明細 |
| 現金流 | 投資收入 | 投資收益、股息收入 | 已支援展開明細 |
| 預算 | 總支出 | `expense.amount` + `advance.ownAmount` 或分攤後金額 | 已支援模式切換與分攤列表 |
| 預算 | 分類支出 | 依 `cat` 匯總個人支出 | 已支援展開明細 |
| 總覽 | 期間收入 | `income.amount` | 待統一展開明細 |
| 總覽 | 期間支出 | `expense.amount` + `advance.ownAmount` | 待統一展開明細 |

## 明細視角

同一筆交易在不同報表中的意義可能不同：

- 在帳戶明細中，代墊顯示為帳戶流出全額。
- 在預算與現金流中，代墊只顯示自己負擔部分。
- 在資產負債表中，代墊未收回部分顯示為應收款。
- 在收入報表中，代墊收款不應被視為收入。

## 建議共用模組

目前建議以 `src/views/transaction-detail-view.js` 作為報表明細共用入口。

它應負責：

- 判斷交易關聯帳戶。
- 計算特定視角下的正負金額。
- 顯示交易日期、分類、帳戶與備註。
- 處理沒有明細時的空狀態。

它不應負責：

- 修改 state。
- 寫入 localStorage 或 Firestore。
- 決定報表總數。

## 下一步追溯清單

後續若繼續打磨，建議依序補：

1. 總覽收入、支出、結餘明細展開。
2. 預算分類明細展開。
3. 代墊應收款明細展開，顯示原始代墊與收款紀錄。
4. 手動資產與手動負債標示「手動項目，無交易明細」。

## 維護檢查點

新增報表或修改報表時，請確認：

- 總數是否能說明來源。
- 點開明細後，金額加總是否能對回總數。
- 代墊與轉帳是否用正確視角顯示。
- 手動項目是否沒有假裝成交易明細。
