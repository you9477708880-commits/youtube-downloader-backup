# 目標中心階段 A 實作紀錄

日期：2026-08-13

## 交付範圍

目標中心已加入原有「預算與願望」頁面最上方，將既有資料整理成兩種視角：

- 準備中：直接取自大額準備金，呈現累積進度、每月提撥、目標月份及可達成性。
- 考慮中：直接取自待購清單，依目前可自由運用金額判斷是否落在配置空間內。
- 需要注意：只有設定目標月份且依目前提撥無法達標的準備金會出現提醒。
- 摘要：沿用既有預算公式的可自由運用金額、規劃提撥與額外補入，沒有建立第二套計算。

使用者可篩選「全部／準備中／考慮中」，也可沿用原有操作查看或調整準備金，以及將待購項目預填到準備金表單。篩選只存在於目前畫面；整份資料替換、登入範圍切換或重新載入後回到「全部」。

## 資料安全邊界

本階段沒有新增持久化欄位，也沒有修改 schema、migration、normalize、JSON 匯入匯出、localStorage、Firestore record codec、Rules 或 Functions。

目標中心是純衍生畫面：

- 帳務仍以 `txs` 為事實來源。
- 準備進度仍由 `sinkingFunds` 及其 events 計算。
- 願望不會被算成支出。
- 「建立準備」只預填既有表單，不會自動建立準備金或刪除願望。

## 自動驗收規格

- 衍生摘要必須與 `calculateBudgetData()` 完全一致。
- 期限不足提醒不得改動原始 state，未設定目標月份時不得製造假警告。
- 使用者文字與 ID 輸出到 HTML 前必須 escape。
- 篩選不得觸發本機保存或雲端同步。
- 桌面預算工作區必須包含目標中心；既有待購預填 smoke 必須從目標中心完成且準備金筆數維持不變。
- 空資料、只看準備中、只看考慮中皆可正常顯示。

## 後續階段

若階段 A 的人工驗收通過，可再決定是否進入階段 B。階段 B 才會評估待購項目與準備金的永久連結；那會涉及資料欄位、刪除語意、同步／匯入與 migration，因此必須另行授權與設計，不能在階段 A 暗中加入。
