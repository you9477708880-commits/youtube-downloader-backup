# 候選版一次性人工驗收（2026-08-29）

用途：確認自動測試無法替代的文字理解、資訊量與真實操作感受。自動化已涵蓋帳務規則、資料隔離、同步衝突、450 筆 CSV 帳戶修復、Emulators 20/20 與 UI smoke 15/15；這裡不要求重新製造危險的雲端衝突。

預估時間：15–20 分鐘。

## 開始前

1. 請 Codex 在 `codex/next` 執行 `npm run preview:acceptance`。
2. 開啟 `http://127.0.0.1:4186`，確認頁首顯示「本機驗收版」與「驗收版｜僅本機」，Google 登入不可用。
3. 若要使用真實資料，只匯入從正式站匯出的 JSON 副本。驗收包使用獨立 localStorage／IndexedDB，不連 Firebase。
4. 不要在這次驗收中測正式帳號刪除、正式雲端覆蓋或真正部署。

## 一次走完的六條路徑

### 1. 總覽與月度回顧

- 選一個有交易的月份，確認收入、生活支出、準備金動用與可自由運用可對回資料。
- 展開「與上期比較」與「財務導航」，確認文字容易理解、沒有好壞評分，也沒有把資產負債快照誤寫成本月變化。
- 手機寬度確認首屏資訊量與折疊後的捲動距離可以接受。

### 2. 記帳、搜尋與生活紀錄

- 搜尋「洗牙」「汽車」或「保養」，切換近 6 個月／全部時間；確認提示明示搜尋期間不影響月度報表。
- 點開一筆長備註交易，確認詳細卡片可完整閱讀，也可直接修改備註、交易類型與帳戶。
- 展開「生活紀錄提醒（不保存）」；輸入關鍵字與間隔，確認能看懂最近日期、平均間隔與預計日期，重新載入後條件不保留。

### 3. 帳戶中心與信用卡

- 到「資產負債」展開銀行與信用卡帳戶，確認餘額、流入流出、信用額度與結帳／繳款資訊容易理解。
- 信用卡消費仍是支出；銀行轉入信用卡的繳款是轉帳，不應再算一次支出。
- 若願意，可在驗收資料建立一筆對帳調整，再刪除；確認它可追溯且不改總覽收入／支出。

### 4. 退休情境與護欄

- 展開「情境比較」，確認三組情境每次只改一個條件，且文字不會被理解成保證。
- 展開「護欄年度檢查」，確認目前／目標股票、債券、現金需各合計 100%。
- 將股票報酬設為負值，確認來源順序優先顯示現金／債券；緊急預備金只有明確勾選後才可使用，資金不足要顯示差額。
- 重新載入後，護欄輸入不保存，也不會建立交易。

### 5. 備份、復原與裝置清理提示

- 打開「衝突復原中心」；沒有歷史時應清楚寫「目前沒有衝突復原紀錄」，而不是讓人猜測。
- 點「清除此裝置的帳務資料」，只檢查第一段提示後按「取消」。提示必須說明處理範圍、可先匯出 JSON，並明示不刪 Firestore 雲端資料。
- 不需要在這次驗收執行最後清除；其 fail-closed、UID 隔離與 Firebase cache 錯誤已有自動測試。

### 6. 電腦與手機整體感受

- 快速切換總覽、記帳、預算、現金流、資產負債、退休。
- 確認沒有水平捲動、按鈕被遮住、文字被截斷卻無法展開，或不清楚「按下後會做什麼」的按鈕。
- 特別回報任何覺得功能重複、首頁太長或學習成本過高的區塊；這些是人工驗收最有價值的部分。

## 通過後的發布順序

人工驗收通過後才執行：合併到 `main` → 推送 GitHub → 等 CI 通過 → `npm run deploy:hosting:production` → 正式站唯讀檢查。Firestore Rules 沒有變更；Firebase Functions 不部署。
