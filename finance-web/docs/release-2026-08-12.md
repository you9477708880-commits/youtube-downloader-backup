# 2026-08-12 維護性與同步整理批次

## 完成內容

- 匯入與匯出流程已抽成 `import-controller.js`。JSON 仍是唯一完整備份；AndroMoney CSV 維持一般交易交換格式。
- DOM 固定事件已集中到 `event-bindings.js`，事件模組只轉送具名 command，不直接持有 store 或 Firebase。
- UID localStorage scope、初次雲端資料判斷、衝突、rollback 與 Auth 流程已集中到 `sync-coordinator.js`。
- revision、outbox、migration、tombstone 與 Firebase listener 仍由既有 `storage-cloud-records.js` 負責，沒有重寫資料同步協定。
- 手動退休資產現在經 `commitState()` 保存，重新整理後不再遺失。
- 固定事件會等 Firebase 初始身份判定完成後才開放，避免啟動期間的 scope replacement 清除使用者剛開啟的匯入預覽。
- `bootstrap.js` 現在主要負責 UI adapter、controller 組裝、Firebase service 建立與初始化。

## 發布後人工驗收

1. 登入 Google，確認頁首顯示帳號且資料正確；登出後確認回到本機資料，不混入登入帳號資料。
2. 新增一筆小額支出，重新整理頁面，確認交易仍存在。
3. 在退休頁關閉資產連動，修改手動資產，重新整理頁面，確認數值仍存在。
4. 匯出完整 JSON；再用同一檔案匯入，確認畫面正常且沒有重複交易。
5. 匯入一份 AndroMoney CSV，確認預覽、帳戶對應、略過／更新重複交易與取消按鈕正常。
6. 用手機與電腦各開一次，確認主要分頁、月度回顧、待購預填及資產負債畫面正常。

若任一步驟出現資料不符，先停止重複操作並保留剛匯出的 JSON；不要用另一台裝置覆寫。回報操作時間、登入帳號狀態與異常步驟即可。
