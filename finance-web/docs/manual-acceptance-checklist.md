## 測試前

1. 先在目前正式網站匯出一份 JSON 備份。
2. 請 Codex 啟動本機預覽，再用無痕視窗開啟。
3. 本機預覽期間保持登出，避免測試資料寫入雲端。
4. 如需使用真實資料驗收，把剛才的 JSON 匯入本機預覽即可；這只是一份測試副本。

## 1. 月度回顧

1. 切到「總覽」，選擇一個確定有收入、支出或大額準備的月份。
2. 找到「月度回顧」。
3. 對照同月份帳本與大額準備，確認：
   - 本月收入沒有漏掉或重複。
   - 被大額準備支付的支出，只把未覆蓋部分算入本月生活支出。
   - 「動用準備」與大額準備紀錄相符。
   - 主要預算使用來源的名稱與金額看得懂。
4. 展開「與上期比較」，確認顯示的前一期間天數相同，收入、生活支出、準備活動與最大分類變化可以對回兩期資料。
5. 確認「增加／減少」只描述金額變化，沒有把消費直接評為好或壞；選擇「全部」等過長範圍時不應出現無意義的跨數十年比較。

通過標準：本期與上期數字都能對回來源，而且文字不會讓你誤以為準備金提撥是帳戶轉帳或把支出變化當成道德評分。

## 2. 待購項目預填大額準備

1. 新增一個暫時待購項目，例如「驗收用相機」、金額 `18000`。
2. 在該項目按「建立準備」。
3. 確認大額準備表單已帶入：
   - 名稱。
   - 目標金額。
   - 每月提撥。
   - 分類與來源備註。
4. 在尚未按「新增準備項目」前，確認大額準備清單沒有自動多出一筆。

通過標準：這個動作只預填表單，不會自動建立準備、交易、`topup` 或 `spend`。

## 3. 資產負債刪除編輯狀態

1. 新增一個暫時的手動資產，例如「驗收舊項目」、金額 `100`。
2. 按該項目的「編輯」。
3. 在仍顯示編輯表單時，按該項目右側的 `×` 並確認刪除。
4. 確認表單標題回到「新增帳戶 / 資產負債」，按鈕回到「新增項目」。
5. 輸入另一個「驗收新項目」、金額 `200` 並新增。

通過標準：新項目可以正常建立，不會顯示成修改已刪除的舊項目。

## 4. 基本畫面檢查

在電腦與手機各快速看一次：

- 總覽、待購清單與資產負債頁可以正常切換。
- 按鈕沒有被遮住，文字沒有超出畫面。
- 新增、編輯、刪除後的提示文字符合實際動作。

## 5. CSV 匯入、登入與雲端同步

這一節請先匯出正式 JSON 備份，再使用一小份可辨識的測試 CSV。

1. 登入 Google，確認右上角顯示目前使用者，而不是「本機模式」。
2. 匯入 CSV 並完成帳戶對應；確認過程中沒有重新載入、登出或出現水平捲動。
3. 匯入完成後，確認提示顯示「已同步雲端」。若顯示「已保存於本機，尚未同步雲端」，先不要覆蓋任何資料並回報。
4. 關閉再重新開啟網站，確認剛匯入的測試交易仍存在。
5. 若出現資料衝突，確認只有「保留雲端」「保留本機」「暫不處理」三個按鈕，不需要輸入英文。

通過標準：Google 登入不中斷、匯入資料可由雲端重新讀回，且桌機與手機均無水平溢位。

## 6. 衝突復原中心（本批新增）

建議用本機預覽與測試資料執行，不要刻意讓正式資料互相覆蓋。

1. 製造一次本機／雲端內容不同的情況，選擇「保留雲端」或「保留本機」。
2. 確認瀏覽器沒有自動下載 JSON，且提示說明落敗版本已存入復原中心。
3. 到總覽的「資料備份與還原」按「開啟衝突復原中心」。
4. 確認只看到目前登入帳號的歷史，內容包含時間、覆蓋方向與逐筆差異摘要。
5. 勾選一筆可辨識的測試交易並復原，確認只有該筆回到舊內容，其他交易不變；重新載入後仍存在。
6. 測試「匯出」會由你主動下載 JSON；測試「刪除」會先詢問且刪除後不再顯示。
7. 以手機寬度確認清單、差異文字與三個操作按鈕沒有水平溢位。

通過標準：一般衝突不再產生大量下載檔、不同 UID 看不到彼此歷史、選擇性復原不影響未勾選紀錄，且復原後能正常同步。

## 7. 帳戶中心與信用卡管理（本機驗收版）

1. 進入「資產負債」，展開一個銀行帳戶，確認可看到目前餘額、本月流入、本月流出與相關交易。
2. 新增或編輯信用卡帳戶，設定信用額度、每月結帳日與繳款日；重新展開卡片後，確認目前欠款、可用額度、本期刷卡、本期繳款與日期提示合理。
3. 信用卡消費仍記為支出；繳卡費請用銀行轉入信用卡的「轉帳」，確認報表沒有把繳款再算一次支出。
4. 在帳戶卡片輸入與目前計算餘額相同的數字，確認不建立調整。
5. 再輸入一個不同餘額，閱讀確認訊息後建立調整；確認帳戶餘額吻合，但總覽收入、支出與預算沒有改變。
6. 到交易清單找到「帳戶調整」，確認可以查看內容；刪除後帳戶餘額回復。
7. 匯出完整 JSON，再於測試環境匯入，確認信用卡設定與帳戶調整仍可還原。AndroMoney CSV 不應包含帳戶調整。
8. 以手機寬度確認帳戶卡片、四格摘要、對帳欄位與按鈕無水平溢位。

通過標準：歷史交易仍連到同一帳戶、信用卡繳款不重複算支出、對帳調整可追溯且完整 JSON 可還原。
