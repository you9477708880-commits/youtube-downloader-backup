# 發布前人工驗收清單

用途：自動測試全部通過後，由使用者確認畫面、文字與操作感受是否符合預期。

目前整批候選請優先使用較短的 `release-candidate-acceptance-2026-08-29.md`。本文件保留完整逐項步驟，只有簡版發現問題或需要重現邊界情境時再回來查閱。

## 測試前

1. 先在目前正式網站匯出一份 JSON 備份。
2. 請 Codex 在 `codex/next` 執行 `npm run preview:acceptance`，再用無痕視窗開啟。
3. 確認頁首顯示「本機驗收版」、右上角顯示「驗收版｜僅本機」，且登入按鈕為停用的「驗收版不提供登入」。
4. 如需使用真實資料驗收，把剛才的 JSON 匯入驗收版即可；它只會寫入 `fin_v7:acceptance:*` 與獨立 IndexedDB，不會讀寫正式 Firebase 或正式版 localStorage。
5. 驗收結束後關閉預覽；需要清除測試副本時，可清除此預覽來源的瀏覽器網站資料。

## 0. 正式 PWA 更新提示（發布後再驗）

這項不能由強制停用 PWA 的本機驗收包自然觸發。本批已用單元與發布邊界測試確認只有使用者按「立即更新」才會切換並重新載入一次；未來發布後若畫面出現更新提示，再人工確認：

1. 提示只有「立即更新」「稍後」，不應自動重新載入正在編輯的頁面。
2. 按「稍後」後可繼續使用；下次重新開啟仍可取得新版。
3. 按「立即更新」後只重新載入一次，登入狀態與目前帳務資料仍可讀取，介面版本已更新。

通過標準：不強制中斷操作、不形成重新載入迴圈，也不因舊 JavaScript／CSS 快取長期看到舊介面。

## 1. 月度回顧

1. 切到「總覽」，選擇一個確定有收入、支出或大額準備的月份。
2. 找到「月度回顧」。
3. 對照同月份帳本與大額準備，確認：
   - 本月收入沒有漏掉或重複。
   - 被大額準備支付的支出，只把未覆蓋部分算入本月生活支出。
   - 「動用準備」與大額準備紀錄相符。
   - 主要預算使用來源的名稱與金額看得懂。
4. 展開「與上期比較」，確認顯示的前一期間天數相同，收入、生活支出、準備活動與最大分類變化可以對回兩期資料。
5. 確認「增加／減少」只描述金額變化，沒有把消費直接評為好或壞；選擇「全部」等過長範圍時不應出現無意義的跨數十年比較。

通過標準：本期與上期數字都能對回來源，而且文字不會讓你誤以為準備金提撥是帳戶轉帳或把支出變化當成道德評分。

## 2. 待購項目預填大額準備

1. 新增一個暫時待購項目，例如「驗收用相機」、金額 `18000`。
2. 在該項目按「建立準備」。
3. 確認大額準備表單已帶入：
   - 名稱。
   - 目標金額。
   - 每月提撥。
   - 分類與來源備註。
4. 在尚未按「新增準備項目」前，確認大額準備清單沒有自動多出一筆。

通過標準：這個動作只預填表單，不會自動建立準備、交易、`topup` 或 `spend`。

## 3. 資產負債刪除編輯狀態

1. 新增一個暫時的手動資產，例如「驗收舊項目」、金額 `100`。
2. 按該項目的「編輯」。
3. 在仍顯示編輯表單時，按該項目右側的 `×` 並確認刪除。
4. 確認表單標題回到「新增帳戶 / 資產負債」，按鈕回到「新增項目」。
5. 輸入另一個「驗收新項目」、金額 `200` 並新增。

通過標準：新項目可以正常建立，不會顯示成修改已刪除的舊項目。

## 4. 基本畫面檢查

在電腦與手機各快速看一次：

- 總覽、待購清單與資產負債頁可以正常切換。
- 按鈕沒有被遮住，文字沒有超出畫面。
- 新增、編輯、刪除後的提示文字符合實際動作。

## 5. CSV 匯入、登入與雲端同步

這一節屬於正式站發布後驗證，不在強制離線的本機驗收版執行。執行前請先匯出
正式 JSON 備份，再使用一小份可辨識的測試 CSV；若本次沒有發布同步相關修改，
可以保留到發布後唯讀／最小寫入驗證批次。

1. 登入 Google，確認右上角顯示目前使用者，而不是「本機模式」。
2. 匯入 CSV 並完成帳戶對應；確認過程中沒有重新載入、登出或出現水平捲動。
3. 匯入完成後，確認提示顯示「已同步雲端」。若顯示「已保存於本機，尚未同步雲端」，先不要覆蓋任何資料並回報。
4. 關閉再重新開啟網站，確認剛匯入的測試交易仍存在。
5. 若出現資料衝突，確認只有「保留雲端」「保留本機」「暫不處理」三個按鈕，不需要輸入英文。

通過標準：Google 登入不中斷、匯入資料可由雲端重新讀回，且桌機與手機均無水平溢位。

## 6. 衝突復原中心（本批新增）

雲端衝突流程不能在強制離線驗收版製造。此節只在專用 Emulator 自動測試或經
明確授權的正式站最小驗證執行，不要為了驗收刻意讓正式資料互相覆蓋。

自動測試已用兩個隔離瀏覽器驗證「相同資料完全不提示」及「真正不同只提示一次、成功存入 IndexedDB 時不下載 JSON」。以下人工項目只用來確認文字與操作感受，不必拿正式唯一資料刻意製造衝突。

1. 製造一次本機／雲端內容不同的情況，選擇「保留雲端」或「保留本機」。
2. 確認瀏覽器沒有自動下載 JSON，且提示說明落敗版本已存入復原中心。
3. 到總覽的「資料備份與還原」按「開啟衝突復原中心」。
4. 確認只看到目前登入帳號的歷史，內容包含時間、覆蓋方向與逐筆差異摘要。
5. 勾選一筆可辨識的測試交易並復原，確認只有該筆回到舊內容，其他交易不變；重新載入後仍存在。
6. 測試「匯出」會由你主動下載 JSON；測試「刪除」會先詢問且刪除後不再顯示。
7. 以手機寬度確認清單、差異文字與三個操作按鈕沒有水平溢位。

通過標準：一般衝突不再產生大量下載檔、不同 UID 看不到彼此歷史、選擇性復原不影響未勾選紀錄，且復原後能正常同步。

## 7. 帳戶中心與信用卡管理（本機驗收版）

1. 進入「資產負債」，展開一個銀行帳戶，確認可看到目前餘額、本月流入、本月流出與相關交易。
2. 新增或編輯信用卡帳戶，設定信用額度、每月結帳日與繳款日；重新展開卡片後，確認目前欠款、可用額度、本期刷卡、本期繳款與日期提示合理。
3. 信用卡消費仍記為支出；繳卡費請用銀行轉入信用卡的「轉帳」，確認報表沒有把繳款再算一次支出。
4. 在帳戶卡片輸入與目前計算餘額相同的數字，確認不建立調整。
5. 再輸入一個不同餘額，閱讀確認訊息後建立調整；確認帳戶餘額吻合，但總覽收入、支出與預算沒有改變。
6. 到交易清單點開「帳戶調整」明細，按紅色「刪除這筆帳戶調整」，確認警告清楚說明餘額會重算；刪除後明細關閉且帳戶餘額回復。
7. 匯出完整 JSON，再於測試環境匯入，確認信用卡設定與帳戶調整仍可還原。AndroMoney CSV 不應包含帳戶調整。
8. 以手機寬度確認帳戶卡片、四格摘要、對帳欄位與按鈕無水平溢位。

通過標準：歷史交易仍連到同一帳戶、信用卡繳款不重複算支出、對帳調整可追溯且完整 JSON 可還原。

## 8. 總覽重複資訊收斂（本機候選）

1. 在「總覽」展開月度回顧，確認仍有摘要、來源明細與「與上期比較」。
2. 確認已沒有獨立「財務導航」與兩個只供心中回答的自評問題。
3. 確認收入、支出仍可由總覽與月度回顧讀取，資產、負債仍可由資產負債頁讀取。
4. 以手機寬度確認移除後頁面沒有空白卡片或不自然間距。

通過標準：沒有重複呈現四個既有數字，也沒有無法記錄或轉成行動的自評區塊。

## 9. 退休情境比較（本機候選）

1. 進入「退休」，設定一組容易辨識的年齡、每月投入、每月提領與目標資產。
2. 展開「情境比較」，確認依序看到目前設定、延後 3 年退休、每月提領減少 10%。
3. 確認延後退休只改退休年齡；降低提領只改每月提領，其他報酬、通膨與目標設定不會自動變更。
4. 調整任一滑桿，確認三組情境結果會一起更新，但重新載入後不會多出新的保存資料。
5. 確認畫面明示這只是敏感度比較，不是投資建議、承諾或保證；手機展開後可以完整閱讀。

通過標準：三種情境差異容易理解、沒有偷偷改設定，且介面複雜度可以接受。

## 10. 退休護欄與提領來源（本機候選）

1. 在「退休」展開「護欄年度檢查」，確認區塊預設收合，並明示「不保存、不自動交易」。
2. 使用 2,000 萬組合、上年度提領 106 萬、起始提領率 5.3%，確認目前提領率及 4.24%／6.36% 上下界容易辨識；5.3% 應標成研究範例，不是保證。
3. 把股票、債券、現金「上年度期初配置」或目標配置改成合計不是 100%，確認畫面直接指出是哪一組未滿 100%。
4. 設期初配置 60%／30%／10%、目標 60%／30%／10%、債券報酬 0%，分別把股票報酬設成 10% 與 20%；確認畫面推估出的目前股票比重與超配金額不同，且先列出「賣出上漲且超過目標配置的股票」。
5. 設股票報酬為負值、期初配置 60%／30%／10%，確認投資組合現金足夠時不會列出賣出下跌股票。
6. 把提領額提高到現金與債券不足；未勾選時確認緊急預備金不動用，勾選後才排在股票之前。若全部來源仍不足，必須明確顯示差額。
7. 把「希望保留的緊急預備金年數」改為 1、1.5、2 年，確認目標金額與目前缺口同步更新；這個輸入不應更改網站既有緊急預備金餘額。
8. 重新載入驗收版，確認護欄輸入回到範例值，交易、帳戶、緊急預備金與同步資料均沒有因試算而變更。
9. 以手機寬度展開，確認配置欄、來源順序與說明文字能完整閱讀且沒有水平溢位。

通過標準：護欄規則與來源金額可追溯、股票下跌時能優先看見現金／債券／經同意的緊急預備金、所有結果均為不保存的試算，且不會建立任何交易。

## 11. 生活紀錄提醒 A（本機候選）

1. 在驗收版匯入一份包含至少兩次「洗牙」或「汽車 保養」的測試資料；兩次日期最好相隔數月。
2. 進入「記帳」，在原本的交易搜尋輸入關鍵字，再展開「檢查這個搜尋的週期間隔（選填）」並輸入自行決定的預期間隔天數；不應再看到第二個關鍵字輸入框。
3. 確認只補充交易筆數、不同日期數、最近一次、距今天數、平均間隔與預計下次日期；同一天多筆不應被當成多次事件，也不應再複製一份「最近三筆」交易清單。
4. 改用兩個關鍵字（如「汽車 保養」），確認交易搜尋與間隔檢查同步更新且必須同時命中；間隔檢查使用截至今天的全部歷史，不受上方近 6 個月或月度報表期間影響。
5. 從既有搜尋結果點交易，確認仍可開啟明細卡片與沿用編輯功能。
6. 清除搜尋或重新載入後確認搜尋字與間隔被清空，但原始交易完全保留；以手機寬度確認輸入與摘要不水平溢位。

通過標準：週期間隔摘要沿用同一套搜尋而不重複明細、能對回原始交易、沒有改變任何報表或帳務、重新載入不保留條件，且文字不會被誤認為醫療／保養專業建議或背景通知。

## 12. 清除此裝置資料（安全驗收）

這項功能具有破壞本機副本的效果。一般先在強制離線驗收版測試；正式 UID 流程只使用可丟棄測試帳號與已完成的 JSON 備份，不要拿唯一正式資料直接測。

1. 在驗收版匯入可辨識的測試 JSON，按「清除此裝置的帳務資料」。
2. 確認第一步列出本機快照、覆蓋前備援與復原紀錄，並明示「不刪除 Firestore 雲端資料」。
3. 按「先匯出 JSON 備份」，確認只下載備份、不執行清除；按「取消」也不應改變任何資料。
4. 再開啟，按「下一步」後確認按鈕改為明確的「確認清除此裝置」，不是模糊的確定／取消或英文輸入。
5. 最後確認後應重新載入，驗收版測試副本消失；正式 localStorage、其他 UID 與共用 device-id 不應被 acceptance 清理波及（已有自動隔離測試）。
6. 正式 UID 的可丟棄帳號若另行驗證：先關閉同網站其他分頁；成功後應登出，重新登入可從雲端讀回。若其他分頁阻擋離線快取清理，畫面應說明先關閉分頁，且本機帳務快照仍保留。
7. 有待同步 outbox／queue／衝突時，未勾選「可能永久遺失」確認前不得清除；這項情境以 fake／自動測試為主，不必刻意破壞正式同步。

通過標準：整個流程至少需要兩次明確操作；取消與失敗均 fail closed；目前 scope 以外資料不受影響；功能從未建立空 state、雲端 tombstone 或 Firestore delete。
